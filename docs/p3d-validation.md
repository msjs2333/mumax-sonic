# P3d：性能与可靠性验收

后续已按用户要求简化实时读取，去掉哈希/历史审计并按当前物理窗口读取，见 [读取简化与复测](p3d-reader-validation.md)。下文保留优化前的验收数据。

2026-09-09。本批交付可复现基准、持续运行检查和故障恢复测试。验收揭示了负载边界；不能将本批工程检查等同于所有实时性能目标已达标。

## 可复现入口

```powershell
python scripts/check_live_soak.py --duration-s 120 --size 64 --audio --dll local/openal-soft/bin/Win64/soft_oal.dll --report local/soak.json
python scripts/check_live_soak.py --duration-s 120 --size 128 --report local/soak128.json
python scripts/benchmark_mumaxplus.py --pairs 4 --steps 80 --size 16 --sample-every 4 --seed 42 --report local/pairs.json
python scripts/benchmark_mumaxplus.py --pairs 6 --steps 400 --size 16 --sample-every 4 --seed 13 --report local/pairs-long.json
```

第一类检查使用解析局域旋转场、完整 XYZ、固定 50 ps 物理采样、默认 20 Hz 墙钟发布和 8 路自适应聚合。`--audio` 明确打开实际 OpenAL 设备，以低音量输出；不带此参数仅计算声音描述。它不包含 Tk 或 GPU，不能代替真实求解器整链路测试。工作集使用 Windows 原生接口读取，其他系统可选 psutil；无法读取时写 null。

第二类检查运行真实 MuMax+：16/64 方形单层、5 nm 网格、Ms=8e5 A/m、A=13 pJ/m、alpha=0.02、Bz=0.1 T、初始 +x、关闭退磁场、每步 5 ps。每个配对重新创建相同 World，随机化基线/监测次序，双方先预热一步并同步。监测包含主机采样和后台 activity 观察，不包含 UI/音频。定时区包含末次完整磁化 eval 同步；后台排空单列。每四步采样，末步强制捕获，若步数不能整除，最后间隔较短，仅用于活动案例，不能当等间隔频谱输入。报告记录脚本哈希、版本、CPU/墙钟时间、采样率、丢帧及最终 XYZ 哈希/最大差异；原始数组不写入报告。

## 本机结果

Windows、RTX 5060 Laptop 8 GiB、MuMax3 3.12、MuMax+ 1.2.1、OpenAL Soft 1.25.2。原始报告与私有设备路径保存在忽略的 local 目录。

- **64² 合成场 + 实际 OpenAL，120 秒**：2344 帧提交和观察，8 路峰值，输入丢帧 0、跳过观察 0、声源意外停止 0、音频控制丢更新 0；HRTF enabled。提交到控制入队 p95 14.05 ms，观察器 p95 8.64 ms；采样到的音频控制应用延迟 p95 0.95 ms。没有做人工听辨、声学回环或 30 分钟运行。此首次运行尚未添加 Windows 工作集回退，RSS 为 null。
- **128² 合成场，无音频，120 秒**：2204 帧提交、2095 次后台观察，输入丢帧 0、合并跳过观察 109；提交到映射完成 p95 151.32 ms，观察器 p95 86.70 ms。工作集从约 37.1 MiB 到 61.6 MiB，峰值 62.3 MiB。这次运行与完整回归部分重叠，属于有竞争负载的样本，不能单独用来定位性能回退。
- **MuMax3 正在求解时桥接**：独立 16² 案例初始帧加 200 次 `Run(5e-12); Save(m)`，共 201 帧；约 10.89 秒完成，退出码 0，原始输出约 0.69 MiB。求解未退出前已有 8 次观察；最终 12 次观察、跳过中间展示 189 次、全部 201 帧解码，缓存仅保留 2 帧/12800 字节，最后帧号 200。末批读取/观察约 271.69 ms。等待期间出现过 stale，随后恢复 current；不能把这一结果描述成逐帧实时或全程无超时。
- **MuMax+ 短成对筛查**：16²、80 步、4 对的墙钟开销分别约 +1.91%、+27.87%、+22.67%、+6.27%，中位 +14.47%；64²、81 步、4 对约 +8.13%、−13.63%、−20.02%、+4.46%，中位 −4.59%。所有最终 XYZ 最大差异均为 0，监测输入丢帧均为 0。负开销是噪声/顺序/调度的表现，不能宣称监测加速，也不能据此宣称 5% 达标。

时间百分位不可直接相加推算端到端 p95。控制应用诊断仅覆盖音频线程调用 API，声源位置/增益另有 120 ms 平滑时间常数，实际耳机延迟仍未知。

128² 独立复测（无其他本项目测试/GPU任务，60 秒）：1128 帧全部由后台处理，队列丢帧/合并跳过均为 0；主循环展示 1127 次，末帧在退出排空时处理。提交到映射 p95 59.32 ms，观察器 p95 36.33 ms，明显低于竞争负载样本。工作集首/末四分之一中位约 39.9/50.5 MiB，峰值约 53.2 MiB；短测中工作集仍有增长，不能据此宣称长期无内存泄漏。

较长 MuMax+ 复测（16²、400 步、6 对，每次 100 帧，整组约 86.38 秒）：开销分别 +40.02%、+1.54%、+30.77%、−16.48%、+0.27%、+4.50%，中位 +3.02%。最终 XYZ 差异全部为 0，输入丢帧全部为 0。各次捕获中位约 0.94–1.44 ms。虽然开销中位低于 5%，离散仍很大，且基线本身从 5.36 到 8.90 秒变化；该证据仍不足以判定开销门槛通过，需要控制 GPU 时钟/竞争/热状态并扩大测量。不能仅挑选中位或最快试次作为验收结果。

## 可靠性证据

完整回归 `python -m pytest -q -rs`：224 项通过。新增真实线程测试覆盖：阻塞观察时队列有界、最旧待处理帧丢弃计数、旧结果正确 stale、新物理帧恢复、频带缺帧后从连续后缀重新预热，以及 finish/fail 竞争时保留错误并丢弃过时工作结果。未发现需要修改生产契约的缺陷。

## 未达标与后续门槛

- 100 ms 应用端预算在小网格样本中有余量，但不是整个实时界面的验收通过；128² 竞争负载和 MuMax3 批量追赶已暴露超预算。
- 额外耗时 5% 原目标针对复用现有输出的低频监测；当前全场直接采样案例不能替代该目标验收。真实高频模式必须单列预算，不能悄悄降低物理采样或粗化磁化场来换通过。
- 仍需 30 分钟设备稳定性、实际端到端声学延迟、真实频带长运行和更充分的监测开销测量。P3d 保持“已有测量工具和首批证据，性能门槛待收敛”，不标成全部通过。
- 下一项优先定位 MuMax3 历史清单/stat 与批量观察成本，并分离采样、观察和聚合耗时；超过可处理速率时继续如实报告合并/丢帧与重新预热。
