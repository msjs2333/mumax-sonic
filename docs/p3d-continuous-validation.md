# P3d：CDW 持续输入验收

2026-09-09。结论：1500×500 场能够持续读取、更新关注区并驱动 8 路原生音频，但 **100 ms 应用端延迟目标未通过，默认 2 秒新鲜度阈值下仍会过期静音**。设备异常停声计数为零不能代替数据连续性验收。

## 节奏与测量边界

原 CDW 记录包含 1001 帧、约 1426.21 秒总运行时间，平均约 0.70 帧/秒。5 ps 是目标物理输出间隔；实际 OVF 保存时间可能有固定步长量级的偏移，测试清单逐帧使用 OVF 头部真实时间。

备份文件修改时间共跨 1406 秒，相邻间隔为 297 个 0 秒和 703 个 2 秒。这种量化时间戳只能支持平均吞吐估计，不能还原精确抖动。本次运行两组连续真实存档输入：

- 平均节奏：每 1.4262103 秒发布下一帧，共 180 秒，四个场景各 45 秒。
- 成批压力：按备份量化时间戳发布，同刻帧连续发布，共 80 秒，四个场景各 20 秒。该组不声称复现原仿真的精确墙钟节奏。

四个场景依次为小圈静止、大圈静止、小圈拖动、大圈拖动；半径分别 0.1、0.4，拖动幅度 0.35，全部开启关注区计算、8 路自适应聚合和 Windows OpenAL Soft HRTF，默认 stale 2 秒。前景保持原体元分辨率，背景两秒刷新。

延迟从原子发布清单开始，到该物理帧第一次完成 OpenAL 控制 API 调用为止。测试通过事件记录关联唯一仿真时间，不以定时轮询估算控制完成。包含实际 OVF 文件读取、后台观察、UI 和聚合等待、音频控制；**不包含原始求解、OVF 写出、MuMax3 桥接稳定等待/解析、设备缓冲或听觉平滑完成**。跨场景边界的结果按完成时刻归属，可能包含上一场景的在途工作。

## 运行中发现的问题

首轮使用帧号乘 5 ps 生成清单时间，部分 OVF 实际保存时间偏移约 0.05 ps，导致一致性检查拒绝输入；已修正测试输入为逐帧头部时间，未放宽生产物理检查。该失败轮不计入上表。

Windows 同时读清单与原子替换会产生短暂 `PermissionError`，曾使首轮发布提前结束。测试发布端现在只对已复现的替换冲突进行最多 0.5 秒有界重试并计数；最终平均节奏测试发生一次重试，压力测试零次。生产桥接路径的对应处理仍需单独核查，未借测试脚本修复宣称整个产品已解决。

## 真实求解器短程成对比较

在本仓库忽略的 local 目录复制原 CDW 脚本与其加载初态，只更改初态引用路径、将 `Run(5e-09)` 缩短为 `Run(1e-10)`。1500×500×1 网格、全部材料/区域/阻尼、50 GHz 激励、固定 50 fs 步长、5 ps OVF 输出和表格输出保持原设置。原项目只读，测试不作科学态分类。

MuMax3 3.12、CUDA 12.9、RTX 5060 Laptop GPU；按关闭→开启→开启→关闭顺序执行。关闭组仍生成相同 OVF；开启组同时运行实际桥接、跟随、Tk、小圈静止关注计算和 8 路原生音频。每次均输出 21 帧，退出码 0。记录的耗时包含求解器进程启动和模型初始化。

| 运行顺序 | 监测 | 求解器墙钟耗时 |
| --- | --- | ---: |
| 1 | 关闭 | 33.787 s |
| 2 | 开启 | 33.544 s |
| 3 | 开启 | 33.901 s |
| 4 | 关闭 | 34.919 s |

关闭均值 34.353 s，开启均值 33.723 s，相对差约 −1.84%。**没有观察到明显减速，但不能解释为加速，也不能据此严格验收 <5%**：只有两对 100 ps 短程运行，启动成本占比不小，且启动前观察到其他应用占用 GPU（约 63% 利用率、2458 MiB 显存），未做全程竞争负载采样。后续需空闲 GPU 下更多重复及较长物理窗口。

两次开启均观察到全部 21 帧，跳过观察帧 0、桥接错误 0、峰值 8 路；末次声音控制的物理时间已到 100 ps。音频异常停止与丢弃控制更新均为 0，音频控制自身 p95 约 0.77、0.92 ms。跟随状态抽样包含求解器初始化等待/过期，不把该总数当作动态阶段的静音时长。四次末帧全部 XYZ 分量逐项比较最大差为 0，仅验证本短程末态一致，不能替代完整动力学对照。

第一次试跑还发现默认 `m*.ovf` 包含 `m_initial.ovf`、`m_drive_end.ovf` 等快照，桥接因非数字序列文件名而返回 invalid，开启组实际没有收到数据。该组明确排除；有效比较显式使用 `--pattern "m[0-9]*.ovf"`。实际 CDW 接入必须相应区分连续输出与命名快照。

## 复现

```powershell
python scripts/check_ovf_continuous.py path/to/paced-manifest.json --phase-s 45 --dll path/to/soft_oal.dll --report local/continuous.json
```

普通 OVF 清单每条记录增加 `wall_offset_s`（相对发布启动的墙钟秒，可相等但不可倒退）；`time_s` 使用真实头部值且在单段内严格递增。清单必须覆盖四个场景的总时长。源文件只读，测试只在临时目录发布清单；原始报告和私有路径留在忽略的 local 目录。

脚本记录各阶段延迟、未完成序号、发布偏差、状态时间、CPU 核当量、RSS 抽样、音频诊断。RSS、状态和帧号差仍由 Tk 约 50 ms 抽样，可能错过短暂峰值。测试范围不是 30 分钟设备寿命测试。
