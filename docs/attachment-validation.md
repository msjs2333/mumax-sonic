# 自动发现与接入验证

2026-10-31。本次为已有仿真的只读接入工作流；不改变求解器脚本、积分参数或用户任务。声音仍由用户主动开启。

## 实现与边界

`--attach` 打开任务选择器；`--attach OUTPUT --all-material` 或 `--mask` 直接连接；`--discover` 仅输出候选 JSON。支持从本机 MuMax3 命令行解析显式 `-o`、`-o=...`，或脚本对应的默认 `.out`。相对路径必须取得进程工作目录，无法取得时明确提示，不猜用 Sonic 的工作目录。

Windows 先通过限时 5 秒的 `tasklist` 过滤 MuMax3，再用 psutil 读取匹配进程；其他系统使用 psutil。当前主机旧版 psutil 的全进程路径解析实测约 12 秒，过滤后一次发现约 2.4 秒。这里只是本机观察，不是跨机器性能承诺。查询失败仍保留指定目录发现。

目录发现仅检查指定根及其直接 `.out` 子目录，默认当前目录。每次最多扫描 256 目录、每目录 4096 条目，跳过符号链接目录，达到限额/权限不足有诊断。PID 与文件存在是不同证据；没有 PID 不等于任务停止，有旧帧不等于仍在运行。显式连接后只轮询选定目录，不进行全盘搜索。

接入从最近的活动 2 帧或频带窗口开始，建立私有临时清单，继承原桥接的半写等待、OVF 物理时间/单位/XYZ 检查。到 4096 条记录时开始新观察段并重新预热；不保存全历史场数组。输出目录消失后等待恢复；断流由现有 freshness 状态静音。源脚本重启、同名文件重写或时间重置需要明确重新连接，不作为连续物理过程。

切换任务和更改观察配方建立新会话并静音；再次点击试听才开启音频。MuMax+ 仍需预设生产线程采样或标准 OVF 输出；无输出的已有任意进程不能自动恢复物理场。

## 自动化与交互检查

- 发现：多任务、路径去重、绝对/相对输出、不可读 cwd、无关进程、浅层目录和扫描限额；Windows CSV 与查询失败回退。
- 接入：空目录等待、半写完成、先有数据再附加、追加帧、stale 与恢复、目录失联恢复、关闭和切换隔离；4105 个历史文件只读取最近有效帧；小上限夹具验证轮换新观察段且原始文件不变。
- Tk/CLI：候选选择、手填目录、材料声明、接入时不打开音频、关闭旧来源、配方切换、JSON 列表、冲突参数拒绝。Tk 对象在主线程回收，避免测试后台线程触发 Tk 析构。
- 包含观察段轮换与静态/松弛重复时间修复的最终全量回归：365 项通过（34.47 秒）。沙箱禁止现有原子发布的 `os.link`，相关测试在获准的非沙箱环境运行，没有改弱发布方式。
- 实际 Windows 无声窗口已检查列表、材料域、切片和接入按钮布局；未开展新一轮人耳/HRTF 验收。
- wheel 与 sdist 包含完整 LICENSE 和 THIRD_PARTY_NOTICES.md，wheel 元数据为 GPL-3.0-only。

## 真实 MuMax3：先启动求解器，再附加

本机 MuMax3 3.12（CUDA 12.9 构建）和 RTX 5060 Laptop GPU。隔离的临时输出目录；测试结束删除自身输出，不接触用户仿真。

```go
SetGridSize(16, 16, 1)
SetCellSize(5e-9, 5e-9, 5e-9)
Msat = 800e3
Aex = 13e-12
alpha = 0.02
EnableDemag = false
B_ext = vector(0, 0, 0.1)
m = uniform(1, 0, 0)
FixDt = 2e-14
for i:=0; i<16; i++ {
    Run(1e-11)
    Save(m)
}
```

`mumax3 -o OUTPUT case.mx3` 独立启动；观察到至少 3 个 OVF 后才进行进程发现与创建 `AttachedSimulation`。结果：

- 发现对应 PID 和输出目录；连接时求解器仍在运行。
- 收到源帧号 6–15 的 10 次后续观察，头部物理时间严格递增，末帧约 1.6016e-10 s。
- 求解器退出码 0，输出 16 帧，停止生产后状态转为 stale。
- 使用 activity 配方，完整材料，poll 0.01 s、stale 0.3 s；没有创建音频设备。

此前 240 帧默认步长案例过快，在发现结束前已退出，只算历史输出验证；60 帧固定步长案例验证了运行中附加但触及测试 30 秒上限，仅终止了测试自身的进程。最后以以上 16 帧案例完成自然退出验证。该实验只验证数据接入，不是材料模型或时间步收敛研究。

## 静态/松弛重复时间修复

独立审阅发现，连续 Relax/SaveAs 输出的真实时间都可能为 0；旧接入将最近两帧送入严格递增动力学时间链，错误拒绝了这些有效快照。

桥接现在对 static/relaxation 仅发布最高数字序号的单帧，每个新快照建立新的观察段。原始 OVF 时间可以重复或回退，仍原样保留，不生成伪造时间间隔。增量读取器按新段清空旧时间历史，单帧拓扑正常计算；activity/band 仍明确返回 unsupported。新序号刷新接收年龄，半写快照保持等待，断流后 stale；dynamic 的严格时间顺序检查保持原有约束。

真实复测使用 MuMax3 3.12、16×16×1、5 nm 网格、Msat=800 kA/m、Aex=13 pJ/m、关闭退磁场：均匀 +x 初始化后 Relax/SaveAs relax0，再切换均匀 +y 后 Relax/SaveAs relax1。原生 vet 和 GPU 运行通过，退出码 0。两帧真实时间均为 0，static 与 relaxation 的 topology 附加均达到 current，读取序号 1、时间 0、矢量 [0, 1, 0]；全部源输出文件内容保持不变。该复测没有打开音频设备。

新增回归覆盖单帧清单、新段增量读取、重复与回退时间、同时间新序号更新、半写/过期恢复、活动与频带禁用，以及动力学重复时间仍被拒绝。
