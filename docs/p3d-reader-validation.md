# P3d：简化实时读取

用户于 2026-09-09 明确要求：这是只读探听工具，去掉不必要的内容哈希、历史防篡改检查和重复验证，以实际处理效率为先。该要求覆盖之前文档中实时链路的哈希审计设计。

## 当前行为

- 实时 OVF 读取不计算 OVF、清单、掩膜内容哈希，也不读取额外时间证据文件做哈希校验。物理时间直接取清单或 OVF 头。
- 已接受的历史序号直接信任，不再 stat、解析路径、重读内容或比对指纹。旧文件修改不会让实时状态失效，也不会重新触发播放；重新运行用新 segment。
- 一批新增帧共用一次公共掩膜和物理说明解析。清单明确给出时间时，只读取观察所需尾部窗口：活动/拓扑保留 2 帧，频带保留完整 N 帧；更早记录只保留轻量时间/序号。缺少显式时间的旧式清单仍需读取头信息获得物理时间。诊断区分实际解码与仅登记时间的记录。
- MuMax3 桥接不再给 OVF/掩膜生成哈希、不检查已发布文件变化，也不反复哈希自己写出的清单。只对新增文件等待两次稳定检查并完整解析，原子发布避免读到半份 JSON。发布清单声明 `integrity: unchecked`，可直接用于跟随和回放。
- MuMax+ 实时捕获不再计算主机数组、坐标和材料域哈希。保留完整 XYZ、物理时间、单位、形状与求解线程约束。
- 保留解释数据必需的检查：时间顺序与阶段、单位/分量、网格和掩膜形状、半写文件、频带预热和有界内存。离线显式带哈希的旧回放格式仍兼容；基准报告的一次性脚本/结果哈希不在实时热路径。

## 测量方法

```powershell
python scripts/profile_ovf_follow.py path/to/live.json --repeats 3 --report local/reader-profile.json
```

脚本只读已完成的清单和源文件，不运行 GPU 或音频。记录新 reader 冷载、相同历史重复加载以及跟随器的读取、帧身份、观察和提交耗时。这里“冷载”指新建缓存，不意味着清空 Windows 文件缓存；cProfile 有额外开销，不能直接充当端到端音频基准。

复测使用前一批真实 MuMax3 的同一份 201 帧数据、16² 网格、末帧号 200。旧实现重复历史检查中位约 251.1 ms；删除历史审计后中位约 7.76 ms（约减少 97%）。最初冷载仍逐文件读取全部 201 帧，耗时约 6.46 秒，分段计时确认几乎全部在读取而非观察；因此进一步改为按物理窗口读取尾帧。

原始剖析报告保存在忽略的 local 目录。此次主要验证只读数据流和数值回归，没有重新进行声学延迟测量或人工试听；原 P3d 的长期设备与监测开销目标仍待收敛。

最终按需窗口复测（三次，中位）：冷载约 **37.99 ms**、相同清单热载约 **5.16 ms**。独立跟随器从读取到观察结果提交约 **53.45 ms**，其中读取约 50.71 ms、观察约 2.72 ms，状态 current，末帧仍为 200。实际解码 2 帧、跳过窗口外解码 199 帧、保留字节数 12800。这表示更快获得当前物理窗口，不代表计算了全部 201 帧的历史观察结果。

完整回归通过 232 项；随后补充跳过帧的物理时间顺序检查，相关读取/桥接测试 25 项通过。测试验证无哈希桥接与回放、MuMax+ 采样无哈希、历史文件不再读取、末帧截断恢复、掩膜形状错误、完整 N 帧窗口及旧版离线输入兼容。
