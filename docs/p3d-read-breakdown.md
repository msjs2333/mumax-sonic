# P3d：读取分段诊断

2026-09-12 整理。接续关注区精简后出现的读取波动，本批先测量，未改动生产读取算法。

## 结论

此前持续测试中 `read_validate` 中位约 123–131 ms；本次独立读取、80 秒窗口复测及带分段计时的 180 秒复测均未复现该慢读。最终读取中位约 24–26 ms、p95 约 27–30 ms。不能据此断言之前的原因已经找到或问题已永久解决，也不能将恢复归功于本批代码优化。

独立读取同一真实帧十次平均约 21 ms；另外读取 16 个不同帧，两轮中位约 25/28 ms，说明该次结果并非只来自反复读取同一文件。系统缓存未清空，运行环境不受控。

## 持续运行中的分段结果

原备份路径、1500×500 CDW 存档场、约 1.426 秒/帧，四场景各 45 秒；目标声源预算 8，stale 保持 2 秒。仅统计 `mumax-sonic-live` 线程，127 个新帧：

| 区间 | 中位耗时 |
| --- | ---: |
| OVF 文件 read 调用 | 4.74 ms |
| 二进制载荷解码与 float64 转换 | 8.02 ms |
| read_ovf 整体 | 13.81 ms |
| FieldFrame 构造及数组复制 | 7.91 ms |
| 掩膜文件 read 调用 | 0.38 ms |
| 清单文件 read 调用 | 0.06 ms |

这些区间有嵌套，不能相加：文件读取和载荷解码已包含在 read_ovf 中，read_ovf 与帧构造又包含在 read_validate 中。均为墙钟时间，可能包含线程调度等待，不是纯 CPU 时间或物理磁盘延迟。

| 场景 | 发布→控制中位 / p95 | read_validate 中位 / p95 |
| --- | ---: | ---: |
| 小圈静止 | 104 / 145 ms | 24 / 27 ms |
| 大圈静止 | 172 / 223 ms | 25 / 28 ms |
| 小圈拖动 | 92 / 151 ms | 26 / 30 ms |
| 大圈拖动 | 180 / 253 ms | 26 / 28 ms |

127 帧全部观察到，126 帧应用有效活动控制，首帧预热；初始 waiting 约 0.06 秒，未抽样到 stale。发布/读取错误、音频异常停止和丢弃更新均为零。CPU 核当量约 1.11，RSS 抽样最大约 221 MB；切换过渡时原生声源抽样最多 11 个，最终为 8。短测不代表长期稳定性或真实内存峰值。

本次仍未全面通过 100 ms p95 目标。测量使用真实归档场及 Windows Tk/OpenAL，不包含求解器、OVF 写出、桥接稳定等待、设备缓冲和听觉平滑完成；未运行新的 GPU 仿真或人工试听。

## 工具与默认开销

新增 `scripts/profile_read_costs.py`，单独解析清单最后一个帧记录，保留材料掩膜和物理元数据，使用与实时一致的 `verify_hashes=False` 路径。只测末帧不等于测试整个增量历史。

```powershell
python scripts/profile_read_costs.py path/to/manifest.json --repeats 5 --report local/read-cost.json
python scripts/check_ovf_continuous.py path/to/paced-manifest.json --phase-s 45 --dll path/to/soft_oal.dll --report local/soak.json --read-profile local/read-breakdown.json
```

持续测试的 `--read-profile` 为显式可选项。计时工具仅在诊断进程内临时包装文件操作和解码入口，退出上下文后恢复；默认应用和未开启该选项的持续测试不加载它。未增加逐帧哈希、历史审计或生产日志。

报告记录线程名、区间、路径及实际请求/返回字节数。持续报告的 `by_thread` 区分读取线程和界面；`fieldframe_construct` 只包装 OVF 加载器入口，不会把 ROI 裁剪混入帧加载。混合文件类型的 `file_read` 总体中位不等于单个 OVF 中位，需按原始样本路径分类。计时记录自身也有开销。
