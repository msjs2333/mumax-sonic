# 通用概念与最小架构

状态：2026-09-08 设计基线；实现均待验证。能力依据见 [MuMax+ 调研](mumaxplus-research.md)，量的定义见 [观测规范](observables.md)。

## 1. 项目定位

MuMax-Sonic 将仿真的物理场、纹理及其演化转换成可解释的空间听觉场。用户可以后台监听变化，也可以主动探听一个静止状态。系统保留同期画面、量值和事件记录，帮助研究者决定何时查看原始结果。

通用性通过明确的物理语义和多案例验证实现，不通过把所有物理场强行压成同一种指标实现。CDW 不提供通用的坐标轴、壁类型、材料、频段、事件阈值或拓扑标签。

首版目标为 Windows 普通耳机。手动 ROI 与空间声源一起实现；头部微调随后加入。完整三维数据可进入契约，但首版观测能力明确限制为二维切片/薄膜及简单实体，不能宣称已支持完整三维拓扑。

## 2. 两种使用方式

**状态探听**：单帧或暂停回放时，主动扫描壁、方向、局域频带统计或拓扑密度；静止结构有可听表示。频带结果必须来自已积累的有效时间窗，单帧不能生成物理频谱。

**动态监听**：强调运动、变化和事件；背景可降低音量，持续数据状态另行标识。变化停止不等于结构消失。

每种方式都显示量名、单位、映射图例、样本时间、数据覆盖率和过期状态。声音增益不是物理量本身。

## 3. 观察模式是配方

| 核心模式 | 主要问题 | 基础输出 |
| --- | --- | --- |
| Activity 活动 | 哪里发生变化？ | 向量夹角速率、选定场的变化或力矩等 |
| Texture / Orientation 纹理与取向 | 对象在哪里、如何移动和旋转？ | 轮廓/区域、连续方向、局部角、运动与形变 |
| Band 频带 | 指定频段在哪里活跃？ | 指定量的滤波包络、振荡强度及可选复相位 |
| Topology 拓扑 | 正负拓扑贡献在哪里、结构怎样变化？ | q、Q+、Q−、Qnet、Qabs、分层/对象读数 |

Domain Wall 是 Texture 的首个专用配方；涡旋、skyrmion、meron 等可组合纹理和拓扑配方。取向是连续变量，flip/polarity 等离散标签仅在所选物理模型和约定成立时派生。

后续配方包括标量探针/收敛、热涨落统计、磁弹两通道、振荡器和多子晶格序参量。只在用户选择时组合有限通道；不默认把全部场、频带和符号同时播放。

## 4. 最小数据流

~~~mermaid
flowchart LR
    A[回放 / MuMax3 / MuMax+] --> B[带物理元数据的样本]
    B --> C[观察器与轻量缓存]
    C --> D[特征场 / 对象 / 事件]
    D --> E[关注加权与声源分配]
    E --> F[声音映射与空间渲染]
    H[鼠标 / 头部姿态] --> E
    D --> G[同步画面和观测记录]
~~~

首版只需一个 Python 包，几个数据结构和观察器函数/类；无需服务注册中心、消息总线或插件市场。每个观察器声明所需实体、量、分量、空间邻域、采样、时间窗和允许缺口；适配器协商成功后才启用。字段支持不能替代物理适用性检查。

## 5. 接口草案

以下是设计字段，不是现有 MuMax+ API。统一 SI 原始坐标和量值，展示单位可切换。

### Sample

- schema_version、run_id、segment_id、sequence、source_reference；保存回放时绑定输入哈希和元数据。
- sim_time_s、monotonic_receive_time、time_kind（dynamics / relaxation / static）；阶段时间重置显式声明。
- entity_id、parent_entity_id、sublattice_id、quantity_name、quantity_definition、unit、component_labels。
- values 的规范布局为 (component, z, y, x)；轴坐标、cell_size、origin、有效材料 mask、边界条件和切片法向独立保存。
- frame_basis、handedness、order_parameter_definition、norm_validity；多实体可以有不同网格，不默认拼接。
- validity、missing_samples、coverage；缺失数据不能用零场替代。

### Observation

- observer_id / version、recipe / config hash、输入引用、物理时间窗和有效覆盖。
- 支持域：field / curve / region / object / scalar；不能强迫所有输出立刻变成点声源。
- values、units、sign_semantics、basis、normalization、uncertainty 或明确的质量标记。
- 对象 ID、位置、空间范围、关联可信度；事件为有时间戳的事实/候选标签。
- invalid / warming_up / stale / unsupported 与有效的 0 分开。

### SonicScene

- 声源 ID、对应 observation、位置/范围、非负 gain、音色、有效期。
- sign_channel / continuous_orientation 等语义仅由显式映射配方转换。
- 总线区分物理声源、结构定位和系统状态。有限声源预算、渐变和峰值限制由渲染侧处理。

以实体身份保存子晶格；优先使用物理定义明确的序参量。AFM 的净 M 可为零而子晶格快速运动；不能用净 M 唯一决定活动和拓扑。

## 6. 关注区域与声音

ROI 是观测后的注意增益场；不改变仿真，也不改变保存的 Q 等物理积分。若另设“分析 ROI”改变积分域，必须单独标注，以免听觉关注操作改写物理统计。

流程为：特征 → 关注加权/保留 → 声源预算分配 → 映射。先选全场最强 N 个再乘 ROI 增益会丢失弱目标。优先预留关注区对象，并保留可选的全局/ROI 外概览声源。

- 前方有限角度声场起步，可旋转物理到听觉的坐标映射，必须显示方向标记。
- 声源位置编码空间位置；符号不抢占左右空间轴。
- 初始尝试 3–4 个同时声源，用稳定区段/区域起步，再根据盲听结果调整。
- 物理强度使用可重现的固定参考尺度与压缩，提供校准；自适应增益只能作为明确模式，不能偷偷抹平衰减或正负不平衡。
- 固定虚拟距离或关闭距离衰减、多普勒，避免虚拟位置污染强度/频率含义。
- 可用宽带/谐波丰富但低刺激的声音提高定位线索；音色、平滑常数、声源数由试听决定，尚未证明最佳。

头部姿态以参考姿态偏差微调基础 ROI，提供限幅、死区、平滑、回中和锁定。姿态失效回到手动状态并提示。注意位置控制与“转头保持世界声场不动”独立，首版头控先实现前者。AirPods 可作普通耳机，姿态硬件方案待单独验证。

## 7. 时间、数据取得和性能

仿真时间用于物理计算；现实时间用于新鲜度；音频时钟用于平滑播放。减慢求解器不能改变同一物理轨迹的速度/频率读数。回放支持固定仿真时间缩放；在线输出携带窗口延迟和样本年龄。

MuMax3 先读已有完整 OVF 与可信时间线。文件出现不代表写完，要检查头、预期数据长度/结束结构并重试；不能仅靠短暂大小不变判断完成。用元数据/manifest 的真实时间，验证单调性，不默认文件编号乘间隔永远正确。Web GUI 图像不能作为定量场输入。

MuMax+ 在已授权的采样点获取量，记录实际 sim_time。Python 分段推进本身可能影响自适应步截断与开销，要用原运行对照；音频模块不擅自修改积分参数。GPU 侧派生量或滤波留到基准证实必要之后。

预览场景可 latest-wins；频带输入和事件检测窗口不能任意抽帧。超载须保留缺口标志、重置/预热相应窗口或退出实时追赶，提供有序回放。事件保存轻量日志，声音调度不应无限重复旧事件；丢弃策略与摘要可审计。

全场导出成本按 网格×分量×精度×现实输出率 衡量，时间窗另算内存。拓扑应在足够分辨率的原场计算后再聚合；不能把渲染分辨率当作物理分辨率。频带先保留时间采样，滤波后再做合适的空间降采样。

## 8. 技术选择与边界

初步选择 Python（NumPy/SciPy）进行观察和配置，OpenAL Soft 原生库负责 HRTF 与音频线程，轻量桌面 UI 展示场、ROI 和图例。UI 框架、Python 音频绑定/ctypes 方案在小样阶段比较；如出现数据分析阻塞音频，再隔离工作进程。OSC、共享内存、Rust/C++ 自研引擎不是首版要求。

通用契约保留实体、单位、序参量、符号和质量；物理后端不足时报告 unsupported。三维 Hopf 指标、Bloch point 分类、非共线序完整拓扑分类、全自动纹理命名和求解器控制均不在首版承诺中。
