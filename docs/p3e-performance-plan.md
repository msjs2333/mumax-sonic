# P3e：后续读取与实时性能收敛

状态：待启动。2026-09-12 从 P3d 转入，不阻塞 P4 泛化验证。本文件是后续工作安排，本批不实施架构改造。

## 进入条件与范围

当实际使用再次受读取长尾、密集输入或频带内存限制影响，或准备严格验收实时性能时，单独启动相关工作包。先冻结输入、物理采样、发布节奏、ROI、声源预算及设备条件，再选择方案；不要求为了开始 P4 先完成本阶段。

| 工作包 | 后续候选方案 | 必须保持的契约 | 验收依据 |
| --- | --- | --- | --- |
| P3e-1 读取与传输 | 比较当前完整 OVF、持续流、共享内存或后端直接输出观察量；按数据选择，暂不承诺某一种 | 单位、XYZ、源帧号、时间、掩膜与半写语义；不硬编码 CDW；默认信任生产输出 | 受控开/关计时交替对照、读取/转换/复制成本、CPU/内存/数据量；同一物理输入数值一致 |
| P3e-2 控制调度 | 文件通知或生产端通知、计算与界面解耦、必要时进程隔离 | 音频线程不读文件或推进求解器；旧结果不恢复失效状态；不积压过期控制 | 分开测发布→观察、观察→控制、实际声学延迟；报告合并、遗漏、预热及长尾 |
| P3e-3 频带局部历史 | ROI 局部时间缓冲、分块频谱或适用频段的流式分析 | 逐点滤波/平方后聚合，采样率、预热、时间窗、移动 ROI 历史缺失均显式处理 | 带内/带外及反相夹具、真实频带输入、ROI 移动、内存上限与长运行；缺历史不是零 |
| P3e-4 严格性能验收 | 受控硬件下重复成对比较与长时间设备测量 | 不用放宽 stale 或牺牲物理采样来伪造提速 | 100 ms 应用端 p95、30 分钟设备运行、低频监测额外开销目标 <5%；各自独立报告 |

这些是待评估的方案，不是全部必须实施。任何新读取方式都先与当前 OVF 路径做小型同输入对照，收益不稳定时停止扩大改动。缺乏依据时不加入逐帧哈希、历史防篡改审计或重复验证。

## 实验和交付要求

- 每轮报告完整帧分母、观察帧与控制应用帧、预热/未应用、stale 和错误；不能用音频线程的零丢弃计数代替全部物理帧已播放。
- 首先对实际慢场景交替测试计时开/关并反转顺序，必要时重复；分位数基于足够场景内样本。保留每轮结果，不只选最快一轮。
- 真正的端到端听觉延迟包括设备缓冲及声音平滑，不能用首次原生控制提交替代。
- 读取与监测开销比较需控制 GPU/CPU 竞争负载，重复关闭/开启监测，分别报告低频复用输出与高频全场模式。
- 验证至少包含一个公开、独立于私人项目的案例。选择哪个案例由 P4a 决定，不预设材料、几何或频段。

P3d 的[暂时收尾记录](p3d-closeout.md)是基线。只有相应验收证据满足目标，才将对应未达标项改为通过；P3d 暂时完成不自动完成 P3e。
