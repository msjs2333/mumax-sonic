# P3d：关注区计算与全链路成本

2026-09-09。本批完成实时活动模式的关注区优先计算，并测量 CDW 尺寸下的读取、观察、聚合、采样、界面和音频控制。小关注区已有可用的局部更新速度；**尚不能宣称真实 CDW 持续运行的端到端 p95 < 100 ms、监测额外耗时 < 5% 或长期无断续全部通过**。

## 使用与物理范围

```powershell
python launch.py --follow path/to/live.json --recipe activity --focus-compute --aggregation adaptive --source-budget 8
```

也可在窗口勾选“关注区优先计算（实时活动）”。同时适用于 OVF 跟随和 MuMax+ 直接流；默认关闭。目前只作用于活动观察器，拓扑、频带和连续取向沿用各自原有计算。

- 关注圈的包围矩形对齐全场 16×16 分块边界，前景保留原体元分辨率计算角变化率，再形成 4×4 局部贡献。计算面积比圆形本身大，诊断报告实际计算体元数。
- 独立后台线程最多每两秒启动一次全场活动计算，保留 16×16 块的贡献和重心；等待队列仅保留最新一对帧。拼接时排除与前景重叠的背景块，后续自适应聚合处理最多 272 个代表量。
- 贡献始终除以全场材料体元数，移动 ROI 不重新定义物理归一化域。但当前前景与缓存背景可能来自不同时间，**两者之和不是全场当前均值**。诊断将该均值设为 `None`，显示背景年龄、时间及计算范围。覆盖只描述已计算贡献，不代表全场即时信息完整。
- 低频背景可能漏掉两次刷新之间的短事件，也不是时间低通滤波。背景尚未就绪时不把缺测区域当作零；关注区无有效材料时仍显示无效并静音。小网格或不足三格的裁剪回退原全场路径。
- 拖动 ROI 可重用已有物理帧，更新次数与新鲜度不增加；过期输入仍会静音。音频线程不读文件、不调用求解器。

## 实测成本

真实 CDW 存档的相邻两帧：1500×500×1，2 nm 间距，5 ps 物理采样间隔，Binary 4 OVF，每帧约 9 MB。材料域依据原仿真几何建立，748700 个材料体元；未用零磁化推断材料。未修改外部项目或启动其求解器。以下分项通常各重复三次，报告中位数；不是端到端延迟分布，不能把分项中位数直接当作端到端 p95。

| 环节 | 本机结果 | 含义 |
| --- | ---: | --- |
| OVF 两帧加载、转换为主机场 | 218.26 ms | 仍读完整场，ROI 未减少文件 I/O；Windows 缓存未清空 |
| MuMax3 桥接两个新文件并发布 | 75.37 ms | 仍完整解析新文件，跟随端再次读取；另一独立测量 |
| 桥接无新文件的一次扫描 | 2.26 ms | 无历史内容哈希；目录规模仍可能影响扫描成本 |
| 只改变帧来源标签 | 0.023 ms | 共享只读负载，免除整帧复制 |
| 全场活动计算 | 488.79 ms | 保留为完整当前场基线 |
| 全场贡献自适应聚合，8 路 | 380.91 ms | 聚合的输入规模曾是另一大热点 |
| 小贡献集聚合，8 路 | 0.45–0.66 ms | 关注区路径以块贡献代替逐体元输入 |
| 声音参数映射 | 约 0.07–0.11 ms | 当前不是主要瓶颈 |
| 后台全场活动及摘要 | 543–680 ms/次 | 独立线程仍消耗 CPU/内存带宽，与前景存在竞争 |

关注圈位于场中心，半径以视图半跨度为单位。前景稳定耗时在首个背景结果完成后测量：

| 半径 | 实际计算体元占比 | 前景中位耗时 | 首次前景耗时 |
| --- | ---: | ---: | ---: |
| 0.1 | 4.66%（34968） | 31.46 ms | 50.64 ms |
| 0.2 | 15.59%（116936） | 109.03 ms | 116.97 ms |
| 0.4 | 50.13%（376000） | 403.96 ms | 404.36 ms |

同一物理帧对的前景加背景贡献，与全场基线均值 371666789.33 rad/s 一致；这验证不重叠和归一化，不证明不同时间缓存仍等于当前全场。大圈仍会超预算；提高声源预算不能补偿未计算的时空细节。

另有不体现在上表计算耗时中的等待：文件桥接默认每 100 ms 轮询，并要求跨两次检查文件大小/时间稳定；跟随器也默认每 100 ms 轮询，ROI 请求沿用该跟随节奏。生产端写文件、等待稳定、发现清单、工作队列、UI 调度与音频驱动都影响最终延迟，不能用 31 ms 前景值代替整条路径。队列满时保留最新帧以限制积压，可能跳过中间事件；频带不能据此假设完整均匀时间序列。下一次端到端记录需包含这些时间戳与丢帧计数。

### MuMax+ 采样成本

另用 RTX 5060 Laptop GPU、MuMax+ 1.2.1、1500×500×1 的独立均匀磁化模型测试。关闭退磁，每次推进 5 ps；首帧预热后重复六次。**只复现网格规模，不是 CDW 物理模型，也不是开启/关闭监测的成对求解开销验收。**

| 环节中位数 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 求解步进并同步 | 45.26 ms | 42.53 ms |
| 独立 `quantity.eval()` GPU→主机传输 | 6.47 ms | 3.41 ms |
| 完整 `sampler.sample()` | 156.68 ms | 11.14 ms |

采样已缓存首帧验证的静态坐标、材料域、层号及后端元数据，避免每帧构造 meshgrid；去掉额外原始场复制，由 FieldFrame 完成一次只读主机副本。采样耗时已经包含一次传输，不能再加上独立 eval 耗时。表中求解和传输波动不应归因于采样缓存。几何在 sampler/segment 内固定；修改几何时创建新 sampler 和 segment，不用逐帧哈希检测变化。

### 实际窗口与音频设备

使用上述真实存档帧，实际 Tk 窗口与 OpenAL Soft 1.25.2，HRTF 开启，8 路自适应声源。运行约 10 秒并移动 ROI；仅为这次静态预览将 stale 阈值设为 30 秒，生产默认仍为 2 秒。

- 绘图 p95 9.65 ms，完整 UI tick p95 20.75 ms。当前背景矢量图已按网格步长抽样，1500×500 场约绘制 13×13 个箭头，不是逐体元绘制。
- 音频控制应用 p95 2.94 ms，8 路活动/目标声源；异常停止 0、丢弃控制更新 0、设备错误无。
- 最后一次前景覆盖 6.99%，计算 60.14 ms；后台耗时 427.82 ms、缓存年龄 1.49 秒。物理更新计数未随 ROI 移动增加，末帧年龄约 10 秒。

这证明存档真实场、实际窗口和原生音频的短时集成可运行。未做人工可辨性判断、声学回环延迟、30 分钟设备测试或真实 CDW 持续输入测试。

## 内存与其他未达标项

单帧 float64 XYZ 加掩膜约 18.75 MB。直接流默认待处理队列从 8 缩到 2，既有负载估算从 375 MB 降到 150 MB，使该尺寸的两帧活动进入默认 256 MiB 接入预算。**这是接入负载估算，不是整个进程的峰值上限**：背景工作帧、观察器临时数组和 UI 引用也会存活。分项脚本 RSS 从约 37 MB 到约 100 MB，只是起止采样，没有测得峰值或长期趋势。

256 帧全场频带仍不可用：仅历史约 4.80 GB，堆叠 XYZ 约 4.608 GB；若生成 complex128 的 129 个频率点约 4.644 GB，实数功率阵列约 2.322 GB，另有归一化和窗函数临时量。上述为数组尺寸估算，不是假定全部同时存活的峰值实测。现有默认预算会拒绝这种输入。

剩余工作按实际收益排序：

1. **文件路径减少重复解码与传输。** 桥接现有完整解析用于确认新 OVF 可用，之后跟随端再读。可研究只检查头部、载荷长度与结束标记的轻量完整性探测，以及按行读取 ROI；目前未实现。长目录枚举和不断增长的 JSON 清单仍需测量，不能因为取消哈希就宣称读取开销恒定。
2. **频带按关注区维护完整时间序列。** 使用局部/分块时间缓冲和选定频段计算，给背景单独声明时空策略；新进入 ROI 的位置需要预热。不能简单降低物理采样率或先空间平均磁化，造成频率混叠、反相抵消。活动优化不能直接当作频带或拓扑优化。
3. **持续输入和资源竞争验收。** 在真实 CDW 的实际输出频率下测源就绪→读取→观察→聚合→音频控制的分布，以及积压、丢弃、RSS 峰值/趋势、CPU/GPU 利用率和磁盘吞吐；再做同设置监测关闭/开启的成对运行。当前各分项不足以推算 <5% 额外求解耗时。
4. **按大 ROI 的实测决定下一次计算优化。** 继续分析角变化率归一化与数组临时量，必要时分块或后端归约。当前半场约 404 ms 明确未满足 100 ms 应用端预算；独立后台线程也不等于免费计算。
